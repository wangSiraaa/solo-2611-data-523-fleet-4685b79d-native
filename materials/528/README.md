# 528 — 事实账本与差额结算

起点已替换为一对可运行、可持久化、可独立校验的服务。`events.json` 仍保留为最小输入样本。

## 运行

```sh
cd materials/528
python3.11 probe.py          # 端到端场景 + 独立校验
python3.11 verify.py <bills.db> <facts.db>   # 仅重新打开数据库做独立核对
```

`probe.py` 覆盖：单表计 100→120（首轮 +20、次轮不再 +20）、跨日部分覆盖、负数退费、撤回后重设、有效期跨两个自然月、同 ID 冲突、重启后幂等、两个连接同时对账。每步用断言固定预期金额。

## 设计选择：事件重放 + 逐日解析

`Facts` 选择**事件重放**而不是物化每日区间：

- 事件只追加，`seq` 是最新的全局递增知识序号；`as_of(k, month)` 回放 `seq <= k` 的事件，按“每个 `(meter, 日)` 由覆盖它的最大 `seq` 取胜”解析。旧认知因此可完整重建，而不是被当前值覆盖。
- **为什么适合本输入规模**：至多 8 个表计、62 天、200 条事实，回放代价极小；同时写入是纯追加，无需维护易错的重叠区间切分。查询旧知识的成本与“读取该截止点的日志并逐日取最大 seq”成正比，更正写入是 O(1) 追加。若事实量级扩大，可再加按 `(meter, seq)` 的物化缓存，但语义仍以日志为准。
- `retract` 以零进入同一条日志，因此“撤回后重设”“部分覆盖”都只是普通重放结果，不需要特殊分支。
- 合法性（`a < b`、至多 62 天且至多跨两个自然月、整数分金额、`op` 合法）在写入前校验；同一事务内做幂等判定，非法输入或 ID 冲突回滚，不留下半条状态，也不消耗序号。
- `event_id` 幂等：同内容重投返回原 `seq`；不同内容抛 `EventConflict` 且不占新序号。日志与 `content_hash`/`canonical` 都落盘，重启后仍幂等。

## 设计选择：不可变封账 + 已提交调整台账

`Settlement` 把“事实应收”和“实际入账”分开：

- `seal(month, k)` 一次性冻结逐表计应收与该知识点，写入 `bills`/`bill_lines`。重复封账只复读同一决定，请求更晚的 `k` 也不会改写已出账单；`bills` 与 `bill_lines` 上还有 SQLite 触发器禁止 UPDATE/DELETE。旧账单字节与旧 `as_of` 结果因此保持不变。
- `reconcile(month, k)` 在单个 `BEGIN IMMEDIATE` 事务内重新读取月份版本，按 `目标应收(k) - (初始账单 + 已提交调整累计)` 计算本轮差额，逐表计保存目标、来源事件、初始额、历史调整与差额，并写一条 `adjustments`/`adjustment_lines`。差额为零也写一条 `no_change` 决定回执。
- **为什么不会重复补收**：调整只以“已提交行”计入累计；两个调用者都看到旧已收额时，第一个提交会推进 `month_state.version` 与 `last_k`，第二个在串行化事务里看到新的 `last_k`：相同 `k` 直接复读原决定（本轮入账为 0），更旧 `k` 返回明确 `STALE` 且不新开收费。因此同一差额只会入账一次，负调整同样进入累计。
- 知识点同月只向前推进：`k == last_k` 复读，`k < last_k` 为 STALE，`k > last_k` 才发布新决定。`resolve_k` 还把 `k` 限定为已提交连续前缀，不依赖墙钟。
- 调整表不可 UPDATE/DELETE；发布中途异常整体回滚，`month_state` 不变。

## 独立算例

`verify.py` 不导入两个服务。它重新打开两个 SQLite 文件，用普通 `{(meter, date): rec}` 字典逐日重放日志求目标额，然后核对：

- 每条封账行等于 `sealed_k` 的字典目标额（旧账单未被新知识改写）；
- 账单内容哈希与所存规范字节一致；
- 每条调整行的 `target` / `initial_bill` / `prior_adjustments` / `delta` 与对应截止点的字典结果一致；
- 初始额 + 所有已提交差额逐表计等于最后结算截止点的字典目标额（即累计已结 = 目标，无重复也无漏计负项）；
- 决定截止点单调、版本号与决定数一致、封账行拒绝 UPDATE。

## 文件

- `facts.py` — 追加式事实账本：`ingest` / `append` / `as_of` / `changes`(=`history`) / `inspect` / `breakdown`。
- `settlement.py` — `seal` / `reconcile` / `statement` / `posted`。
- `verify.py` — 独立逐日字典核对器。
- `probe.py` — 端到端场景、并发与重启幂等断言。
